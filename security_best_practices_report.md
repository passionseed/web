# Security hardening review

Reviewed 3 November 2026. Scope: the Next.js application, authentication proxy,
selected privileged and public API handlers, upload guards, redirect handling,
and the production dependency graph. This is a source review and local
verification, not a penetration test or a certification of production security.

## Executive summary

This change patches known critical dependency advisories, rejects unsafe return
URLs, closes the page-authentication exception path, preserves cookie attributes
on redirects, and adds same-origin checks to admin API mutations. The production
dependency audit changed from 8 critical / 94 high / 120 moderate / 25 low to
0 critical / 4 high / 22 moderate / 6 low. Counts are registry advisories, not
confirmed exploitable application paths, and can change as advisories are added.

The changes are local. Production protection requires deployment. Remaining
high-severity advisories and production configuration still need follow-up.

## Critical findings addressed

### 1. Vulnerable framework and dependency versions

Rule: NEXT-SUPPLY-001. Evidence: the original `package.json` declared Next.js
16.2.1, jsPDF ^3.0.4, and older AWS S3 SDK dependencies. `pnpm audit --prod`
reported critical advisories in Next.js, jsPDF, and fast-xml-parser through AWS.
**Impact:** affected dependency features could permit remote code execution,
file access, or injection; applicability varies by feature and deployment.

Fix: Next.js 16.4.4, jsPDF 4.2.1, current AWS S3 SDK packages, Axios 1.21.0,
and sanitize-html 2.18.1. Refreshed compatible vulnerable transitive packages.
Scoped overrides patch legacy Axios, lodash-es, and nanoid 3 pins without
changing their major versions. Removed unused `git`, `lazy`, `lazygit`, and
`react-force-graph`; the application retains its imported 2D graph package.
Specific Next.js release-age exceptions generated by pnpm are limited to this
security update. No general supply-chain policy exemption was added. CI now
checks production dependencies and blocks critical advisories; existing
non-critical debt remains visible in audit output. The CI token has read-only
repository permissions.

References: [Next.js advisory](https://github.com/advisories/GHSA-vcvr-r3jv-pc5j),
[jsPDF advisory](https://github.com/advisories/GHSA-wfv2-pwc8-crg5).

## High findings addressed

### 2. Authentication exceptions allowed protected page requests through

Rule: NEXT-AUTH-001. Location: `utils/supabase/proxy.ts:131`.
The previous catch block returned the ordinary next response if verification
threw. That removed the page gate during authentication failures; downstream
authorization and RLS could still protect particular resources.

Fix: use `getUser()` in accordance with repository rules, return HTTP 503 with
`Cache-Control: no-store` for protected pages on exceptions, and retain public
page availability. Cookie copying now retains Secure, HttpOnly, SameSite,
expiry, and path attributes. Actual resource authorization must continue to
happen in route handlers and data access code.

### 3. Admin cookie-authenticated mutations lacked an origin check

Rule: NEXT-CSRF-001. Location: `proxy.ts:28` and
`lib/security/request-origin.ts:4`.
Admin routes checked roles but no shared browser request-origin check was visible.
SameSite cookies provide partial mitigation, not a complete origin boundary.

Fix: mutating `/api/admin/` requests require a matching Origin, or a matching
Referer when Origin is absent. Explicit cross-site requests are rejected.
The proxy matcher explicitly includes all API paths, including IDs ending in
asset suffixes. GET/HEAD/OPTIONS are unaffected, and webhooks outside the admin prefix keep their
own authentication. Non-browser admin scripts must send the application's
matching Origin. This is defense in depth; it does not replace per-route auth.
Origin checks for non-admin cookie-authenticated mutations remain a follow-up.

## Lower-severity findings addressed

### 4. Return URL validation missed URL normalization tricks

Rule: NEXT-REDIRECT-001. Severity: Low. Location:
`app/auth/callback/route.ts:51`, `app/login/page.tsx`, `app/onboard/page.tsx`,
and `app/hackathon/onboarding/page.tsx`.
Prefix-only checks accepted some browser-normalized external destinations;
login also accepted protocol-relative destinations.

Fix: shared `safeRedirectPath` rejects protocol-relative URLs, backslashes,
control characters, and non-local destinations while preserving local paths,
queries, and fragments. Tests cover malformed destinations and existing SHIFT
OAuth flows.

## High findings still open

### 5. Zod 3 dependency advisory requires migration planning

Rule: NEXT-SUPPLY-001. Location: `package.json`, `dependencies.zod`.
The installed 3.25.76 release is reported vulnerable to memory exhaustion while
validating oversized constrained collections. The registry identifies >=4.6.6
as patched; no newer 3.x release was available during this review.

Next action: migrate application schemas and dependent integrations to a patched
Zod 4 release, test schema error handling and AI structured output, and verify
request size limits at each public validation boundary. No exploitability claim
is made for every schema using Zod 3.

### 6. Diagram conversion retains nanoid 4

Rule: NEXT-SUPPLY-001. Location: `pnpm-lock.yaml`, dependency chain
`@excalidraw/excalidraw > @excalidraw/mermaid-to-excalidraw > nanoid@4.0.2`.
Three high advisories remain on this dependency. There is no patched nanoid 4
release listed by the registry.

Next action: upgrade or replace the conversion dependency with a supported
nanoid major, then verify diagram import, generated identifiers, and whiteboard
flows. A forced major override was deliberately avoided without that validation.

## Verification and limitations

- Focused behavioral tests cover redirects, failed identity verification, cookie
  security attributes, admin origin validation, and proxy integration.
- Focused regression suite: 5 suites, 46 tests passed.
- Repository lint: passed with 2,460 existing warnings and no errors.
- Final production build: passed on Next.js 16.4.4. The existing build config
  ignores TypeScript errors, so this is not a separate type-check result.
- pnpm 10 frozen-lockfile validation: passed, matching the CI package-manager
  major. Production audit gate at critical severity: passed.
- jsPDF certificate-sized document export smoke check: passed.
- Full-suite result is recorded below.
- Local database security-lint tests report no reachable local database. This
  review does not establish the deployed database's RLS, grants, view ownership,
  or function privileges. No production migrations were applied.
- Existing debug guards, upload permission checks, and role lookup helpers were
  inspected; their presence is not a claim that every API or server action has
  been exhaustively verified.
- Live Vercel headers, environment secrets, webhook configuration, rate limits,
  storage permissions, and historical secret exposure were not verified.
- Strict Content Security Policy needs an inventory of the app's script, iframe,
  and media integrations before enforcement. Existing security headers remain.
- No production deployment or Vercel preview was performed.

See [Next.js authentication guidance](https://nextjs.org/docs/app/guides/authentication)
and [Supabase getUser](https://supabase.com/docs/reference/javascript/auth-getuser)
for the server-side verification boundaries used in this review.

Full root suite: 226 suites passed, one skipped; 1,694 tests passed, eight
skipped. The initial run also picked up an independent `.claude/worktrees/`
checkout and failed its live-database test. Jest now excludes that nested
checkout, matching the existing `.worktrees/` exclusion; root integration test
requirements were preserved. The root suite then passed.

Changes remain local on `fix/security-hardening`. No production changes were made.
