## Problem Statement

First-time SHIFT students stall on Day 2. Install (OpenCode + gstack) eats mentor time, `/office-hours` asks too much and leads nowhere observable. Mentors can't see who finished or what's next. Teaching step-by-step contradicts SHIFT goal: minimal teaching, maximal agency (SDT).

## Demand Evidence

- All 9 SHIFT1 students ran `/office-hours`, mentors still don't know who finished or what's next. Zero finish visibility.
- Discord check-ins get mostly no answer. Mentors fall back to 1:1 screenshares.
- 20min install slot for 5min job. 4x tax inside 2hr Day 2 block (install + summary + prototype + QA + MVP).
- Knight (mentor) signal: office-hour asks too much, leads nowhere. Wants opinionated scalable run for SHIFT2.
- Behavior > opinion: silence + screenshare load is real usage cost, not vibe.

## Status Quo

- Day 2 flow per `company-brain/shift.md`: tell-what-happened (20min) → install OpenCode+gstack (20min) → summary + problem statement → AI check → paper prototype → `/office-hours` QA (10min) → MVP in AI Studio.
- Install prompt assumes terminal comfort first-timers lack. Most need screenshare guide.
- QA output has no fixed artifact. No scope-card, no next-step, no telemetry file. Mentors re-ask in Discord, get silence.
- Workaround cost: mentor per-student triage, Day 2 overruns, agency drops as mentors decide for students.

## Target User & Narrowest Wedge

Primary: Knight M5 archetype. M5 student, HP work laptop, holiday build, never used terminal, portfolio goal. Secret goal from us: SDT growth (autonomy, competence, relatedness).

- Promoted by: shipped live project + พอร์ต 1 หน้า with real user evidence.
- Fired by: stalling out, outsourcing thinking to AI/mentor, quitting.
- Up at night: Day 2 install + blank page, fear of looking dumb on Discord.

Secondary: SHIFT mentors (Knight et al). Need scale without 1:1 screenshares.

Narrowest wedge (intrapreneurship frame: smallest demo getting sponsor greenlight): one opencode-native `/seedstack` run producing one scope-card + next-step + telemetry line before SHIFT2. Not full platform. Proves finish visibility fastest.

## Constraints

- Socratic, never answers. Pushes research. Asks, doesn't tell. (user-stated, non-negotiable)
- Minimal teaching. Students first ask self, then AI for more info, before building. Prompt formula card only.
- Student owns choice + change of direction + ugly ship. SeedStack narrows scope, never picks direction.
- Opencode-native, not Claude-only. Must run on student laptops (Windows/Mac) in Day 2 block.
- Discord-only support. Outputs postable to #progress. No slides. Peers answer first.
- Students type every install command themselves. AI explains and diagnoses, never runs installs for them.
- Telemetry goes to our server, keyed by `student_id` (account linked to Discord). Students are minors: RLS on, mentor-only reads, no public dashboards.
- No implementation in this doc. Design only.

## Premises

1. Primary user = first-time SHIFT student (Knight M5 archetype). Mentor scale is secondary win. — agree
2. Core job = finish visibility, not smarter questions. Guided install, one artifact out, clear next step, server telemetry. — agree
3. Opencode-native, no Claude dependency. Runs in Day 2 block, survives Discord-only support. — agree
4. SDT guardrail: student owns choice + change of direction + ugly ship. SeedStack narrows scope, never decides. — agree
5. Added in session: Socratic research-push over answer-giving. Every AI step ends with question + self-research task. — agree

## Approaches Considered

### Approach A: Single Skill Shim
Summary: One opencode skill wrapping existing gstack `/office-hours` with fixed scope-card output + file telemetry. No install change.
Effort: S
Risk: Low
Pros:
- Ships in days, proves finish visibility before SHIFT2.
- Reuses gstack prompt directly, smallest diff.
Cons:
- Leaves install pain unsolved.
- No server telemetry, no mentor view.
Reuses: gstack office-hours prompt, opencode skill format.

### Approach B: SeedStack Suite (chosen)
Summary: 3-step opencode-native chain: install-doctor → scope-lock (Socratic) → ship-check. Each step emits artifact + telemetry event to our server. Student ships on own Vercel + Supabase via CLIs they installed.
Effort: M
Risk: Med
Pros:
- Solves install + QA + output in one opinionated path.
- Telemetry gives mentors scale without screenshares.
- Socratic research-pushes preserve agency at each gate.
Cons:
- More files than shim, needs 2 student test runs before SHIFT2.
- Longer install: Node, git, OpenCode, Vercel CLI, Supabase CLI + 2 account logins.
- Model/account + cost question still open (see below).
Reuses: gstack office-hours diagnostic core, SHIFT Day 2 Excalidraw artifacts, prompt formula card, opencode skill spec.

### Approach C: No-install Runner
Summary: Bypass install on Day 2. Shared prompt cards + Excalidraw-first flow, outputs saved to #progress. Local skill habit deferred.
Effort: M
Risk: Med
Pros:
- Zero laptop friction for SHIFT2.
- Fastest agency test without tooling tax.
Cons:
- No local skill habit built, weaker long-term SDT tooling.
- Still needs install story for Day 4 web-app path.
Reuses: Day 1 interview prompt, paper prototype examples.

## Recommended Approach

B SeedStack Suite. User overrode minimal-viable recommendation (A) for full chain. Reason: telemetry + install fix is core demand (don't know if finished), shim leaves biggest tax untouched. Ships as narrow suite: 3 skills max, each with single artifact, strict stop rules.

AI Studio dropped. Students deploy to their own Vercel + Supabase accounts through CLIs. Installing the toolchain themselves is part of competence: they leave SHIFT able to ship a new project alone.

Suite outline:
0. Bootstrap page (outside OpenCode, since the doctor can't run before OpenCode exists): OS toggle Mac / Windows. Mac: Terminal one-liner. Windows: PowerShell one-liner; cmd users told "open PowerShell" as step 0. Installs OpenCode + SeedStack skills only.
1. `seedstack-install-doctor`: OS-detect, one tool at a time: Node → git → Vercel CLI → Supabase CLI. Shows the command, student types it, pastes output back; doctor reads errors and explains next step. Then `vercel login` + `supabase login` (browser auth by student). Stop: `node -v`, `git --version`, `opencode --version`, `vercel whoami`, `supabase projects list` all green. Fail path posts check status to server + log snippet to #ถามได้ทุกเรื่อง.
2. `seedstack-scope-lock` (Socratic): reads interview summary + problem statement (`[Who] struggles with [what] when [situation], because [why]`). Asks up to 3 questions per turn, each ending with research task (talk to 1 human / find 1 method). No round cap: student decides when scope is locked ("ล็อก"). Output: `scope-card.md` (problem, first 15–20 reachable users, explicit non-goals, next MVP test). Never proposes solution text.
3. `seedstack-ship-check`: reads scope-card + paper prototype photo/desc. Checks: real user named? Test planned in 48hr? Student stated what they cut (doctor checks a cut exists, never decides it)? Output: `ship-ticket.md` (MVP scope, 3 user tests, evidence to post). Student deploys with `vercel deploy`, Supabase for data if needed. Live URL goes into ship-ticket + telemetry.
- Telemetry: each step POSTs `{student_id, step, done, minutes, next, live_url?}` to `/api/seedstack/events`, authenticated with student's PassionSeed account token. `minutes` measured from step start to done event. Mentor dashboard shows per-student status + live links. Local JSONL only as offline fallback, synced on next run.
- SDT mapping: autonomy (owns scope-cut + changes of direction + when to lock), competence (installs own toolchain, ships + tests, better questions over week), relatedness (peer-first Discord, group install help, prompt library).

## Success Criteria

- All install-doctor checks green within the planned install budget for ≥80% of students, zero mentor screenshares for them (cohort ~10: track count, not percentiles).
- 100% runs emit scope-card + ship-ticket + server event. Mentor dashboard shows finish without asking.
- Every student has a live Vercel URL by Day 5, deployed by them.
- Discord #progress posts per student on days 3/5 without reminders (autonomy behavior).
- Scope-cards show explicit non-goals + named 15–20 reachable users.
- Students change idea due to customer evidence at least once per cohort (sample).
- Day 7: confidence to start new project solo ≥4/5 median (ask Day 1 too for baseline), with shipped MVP + user tests as behavior anchor.
- Zero answer-giving violations in sampled transcripts (mentor reviews 3 per cohort): every AI turn ends with question/research task.

## Distribution Plan

- Ship as opencode-native skills in repo: `seedstack/` skill dir (SKILL.md per step + templates for scope-card/ship-ticket) + `docs/designs/seedstack.md` (this doc, repo copy).
- Students start from bootstrap page (Mac / Windows PowerShell one-liner), which installs OpenCode + SeedStack skills. Mentor guide image in #อ่านก่อน links bootstrap page + channel map.
- Server side: `/api/seedstack/events` route + table (RLS, mentor-only read) + mentor dashboard page in this web app.
- Validation: 2 dry runs with SHIFT1 students before SHIFT2, at least one on Windows. No binary, no store.

## Dependencies

- `company-brain/shift.md` Day 2 flow + open questions (model, laptops, runner).
- gstack `/office-hours` diagnostic core (to slim, not fork blindly).
- Opencode skill spec for native format.

- PassionSeed student account auth usable from CLI (token for telemetry POST).
- Vercel CLI, Supabase CLI, Node, git on student laptops.
- 2026 scaffolding literature (VibeLearner/CodeExemplar): withhold solutions, preserve struggle.
